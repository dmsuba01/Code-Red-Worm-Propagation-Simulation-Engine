Delayed Patching Response Analysis: Scenario 4 vs Scenario 5

Quantifying how response latency alters outbreak inflection and peak compromise

Scenario 4: Prompt Countermeasures (T = 0)

Human countermeasures (disinfection, patching, and edge router filtering) begin immediately as soon as the first scans are observed.

Result: Susceptible hosts are pre-immunized while active infections are continuously cleaned, capping maximum saturation at 67.8% and shifting peak active infections to t = 155.

Scenario 5: Delayed Patching Response (T = 250)

Admins do not respond during the first 250 time steps while signatures are analyzed. No patching or filtering occurs until t = 250.

Result: During the initial delay window, the worm propagates unchecked. Total compromised hosts surge to 318,298 (88.4%) with active peak infections reaching 291,556 hosts.

Key Cybersecurity Finding: Delaying patching by 250 steps allows the worm to breach the 50% inflection point, causing an additional +74,218 servers to be compromised worldwide (+20.6% higher saturation).

OpenMP Parallelization Strategy

  • Monte Carlo Domain Decomposition: 100 independent trials distributed via #pragma omp parallel for schedule(dynamic).
  • Lock-Free Thread RNG: Each OpenMP thread uses an independent 64-bit SplitMix64 pseudo-random generator state, completely eliminating atomic lock contention.
  • Dynamic Scheduling: Handles load imbalance between runs that terminate early due to rapid eradication vs full 2000-step runs.

Roofline Model Diagnosis: Memory-Bound

  • Peak Hardware Compute: 780.0 GFLOP/s (14-Core CPU)
  • Peak DRAM Bandwidth: 76.8 GB/s → Ridge Point: 10.16 FLOPs/Byte
  • Simulation Operational Intensity: 1.82 FLOPs/Byte
  • Finding: 1.82 << 10.16 → Strictly Memory-Bandwidth & Cache Bound. Host state updates dominate over arithmetic.
